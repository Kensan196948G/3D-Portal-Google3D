1はじめに

① 止めない

支店の工事部・作業所・本社の各本部が、見たいときにいつでも開ける。止まってもすぐ気づいて直せる。

② お金をかけすぎない

Google の料金が、思わぬ額にならないように上限と見張りをつける。請求先は会社のものだけを使う。

APIキーが悪用されないようにし、Google の利用条件と社内規程を守る。

④ 記録を残す

いつ・だれが・何を変えたかを残し、社内の点検や監査に答えられるようにする。

2システムの構成

2.1構成図

大事なのは、Google の3Dを取りに行くのはサーバではなく利用者のPCだということです。そのため、社内の各PCから ②③ への通信が FortiGate で許可されている必要があります。

2.2通信の一覧

当社の FortiGate は、外への通信を許可した宛先だけ通します。下の表は版1.0（埋め込み版）のものです。サーバ版では国土地理院・気象庁・ハザードマップポータルなども必要です。許可する宛先は 14.2 の一覧に従ってください。

FortiGate の設定で気をつけること
  • ②③ のドメイン（FQDN）を許可する宛先に入れ、Webフィルタでもブロックされていないこと。
  • SSLの中身を検査（SSLインスペクション）している場合、社内のPCが FortiGate の証明書を信頼していること（信頼していないと、ブラウザがつながらない）。うまくいかない場合は、②③ を検査の対象から外すことを DX推進部で検討します。
  • Google の3Dはデータ量が多い（あちこち見て回ると1回で数百MBになることもある）ため、帯域の制限やアプリ制御で遅くならないこと。
  • 宛先を絞る方針に合わせて、許可は 14.2 の一覧だけにします（サーバ版は国土地理院・気象庁へも利用者のPCから取りに行くので、版1.0 と違い許可が必要です）。
  • 許可を足した・外したときは、変更の記録（付録C）に残します。

個人の Google アカウントでプロジェクトを作らないでください。DX推進部が管理する会社用のアカウントで作業し、権限は担当者だけにします。会社用のアカウントをどの方式で用意するか（だれのメールアドレスで作るか、何人に権限を持たせるか）は DX推進部で決めて、記録に残してください（未確認）。

3.1地図専用のプロジェクトを作る

  1. 上部のプロジェクト選択 → 新しいプロジェクト を押します。
  2. 名前を付けます（例：mirai-site-portal-3d）。ほかの用途のプロジェクトと分けると、料金と権限が混ざりません。
  3. 作成 を押し、できたプロジェクトを選びます。
  4. プロジェクト名・作った日・管理者を、資産の台帳と付録Cの記録に書きます。

3.2請求先アカウントをリンクする（必須）

ここを忘れると、つながりません

請求先アカウントがリンクされていないと、キーが正しくても Google から「404 Requested entity was not found」が返り、3Dが出ません（原本の試験で、実際にこの原因で接続できなかった事例があります）。無料の範囲だけで使う場合もリンクが必要です。

  1. 左上のメニュー → お支払い を開きます。
  2. 「このプロジェクトには請求先アカウントがありません」と出たら、請求先アカウントをリンク を押し、会社の請求先アカウントを選びます。個人の請求先アカウントは選びません。
  3. お支払い画面に、会社の請求先アカウントの名前が出ていれば完了です。

3.3Map Tiles API を有効にする

  1. https://console.cloud.google.com/apis/library/tile.googleapis.com を開きます。
  2. 青い 有効にする を押します。管理 と出ていれば、すでに有効です。

3.4APIキーを作って制限をかける

  1. APIとサービス → 認証情報 → 認証情報を作成 → APIキー を押します。
  2. できたキーの名前を分かりやすくします（例：mirai-site-portal-3d-社内）。
  3. アプリケーションの制限で ウェブサイト を選び、使うサイトを1行ずつ追加します（下の表）。
  4. API の制限で キーを制限 を選び、Map Tiles API だけにチェックを入れます。
  5. 保存 を押します。反映まで最大5分かかります。
  6. キーの名前・使い道・制限・作った日を、APIキーの管理表（付録C）に書きます。キーの値そのものは書きません。

ブラウザは Google へ「サイト名」（例：https://portal.example.local/）だけを送ります。そのため https://portal.example.local/portal/* のようにフォルダ名まで入れて登録すると一致せず、拒否されます。必ず サイト名＋/* で登録してください。

キーは「社内用」「社外公開用」「試験用」など、使い道ごとに分けると、止めるときに影響を小さくできます。

3.5予算アラートを設定する

  1. お支払い → 予算とアラート → 予算を作成 を押します。
  2. 対象を会社の地図専用のプロジェクトにします。
  3. 金額を決めます（例：月 1,000円。これは計算のための例で、会社として決めた予算額ではありません。金額は DX推進部が決めます）。

4.3nginx の設定

  • 時刻：証明書や記録の時刻が狂わないように、時刻合わせ（chrony／systemd-timesyncd）が動いていることを timedatectl で確かめます（「System clock synchronized: yes」）。

4.8社外からの利用（SSL-VPN）

出張先など社内網の外から使うときは、FortiClient の SSL-VPN で社内網に入ってから開くのを基本とします。ポータルをインターネットに直接公開しません。

  • SSL-VPN でPCに割り当てられるIP帯が、nginx の allow（付録A）に入っていること。入っていないと 403 になります
  • SSL-VPN の設定（すべての通信を社内経由にするか、社内あての通信だけを通すか）によって、②③ への通信が FortiGate を通るか、利用者の回線から直接出るかが変わります。当社の設定は DX推進部で確かめてください（未確認）。社内経由の場合は、2.2 の許可がそのまま必要です
  • Google の3Dは通信量が多いため、SSL-VPN の帯域に余裕があるかを確かめます。遅い場合は、簡易地形モード（Google につながない）でも使えることを案内します
認証付きの公開（Cloudflare Access 等）

SSL-VPN を使えない人（社外の関係者など）に見せる必要があるときは、Cloudflare Access 等の認証付きの公開も考えられます。使うかどうか、だれに見せるか、どの方式にするかは DX推進部が判断します。決めるまでは使いません。社外の人に見せるときの注意は 5.5 です。

6.2アクセス記録の見方

ポータルを1回開くと、ふつう Google の課金が1回数えられます。nginx の記録から、開かれた回数の目安が分かります。

# 今日、ポータルが開かれた回数（200=新しく取得、304=キャッシュの確認） sudo awk -v d="$(LC_ALL=C date +%d/%b/%Y)" '$4 ~ d && $7 ~ /^\/(index\.html)?(\?.*)?$/ && ($9==200||$9==304)' \ /var/log/nginx/site-portal.access.log | wc -l # 日ごとの回数（記録に残っている期間） sudo awk '$7 ~ /^\/(index\.html)?(\?.*)?$/ && ($9==200||$9==304){split($4,a,":"); print substr(a[1],2)}' \ /var/log/nginx/site-portal.access.log | sort | uniq -c # よく開いているPC（IP）上位10 sudo awk '$7 ~ /^\/(index\.html)?$/{print $1}' /var/log/nginx/site-portal.access.log | sort | uniq -c | sort -rn | head

  4. ③ の sites_runtime.json（または台帳の画面）で、工事名と所在地（都道府県・市区町村）が合っているかを全現場について確かめます。

  • 現場の位置・地形・工種は specs.json の順番で、工事名・支店・発注者は SITE_DEFS の順番で結びつきます。順番がずれてもエラーは出ません。工事名や担当支店が、別の港の位置に付いてしまいます。
  • 工種のテンプレートは specs.json の kind で決まります。SITE_DEFS 側の工事名と工種が合っているかも確かめます。
  • 工事番号（仮採番）は、支店・着工年度（4月始まり）ごとに、この並び順で連番を振ります。並びを変えると、ほかの現場の工事番号も変わることがあります。

8APIキーの管理

APIキーの発行・入れかえ・削除・漏れたときの対応は、すべて DX推進部（Google Cloud 管理者）の作業です。利用者は、DX推進部から受けとった会社のキーだけを使います。

8.1キーの約束

  • キーは DX推進部が、会社のプロジェクトで発行する。個人のキー・個人の請求先のキーは使わない
  • キーは「ウェブサイトの制限（サイト名/*）」と「Map Tiles API のみ」の2つの制限を必ずかける
  • キーは使い道ごとに分ける（社内用・社外公開用・試験用）
  • キーをメール・チャット・desknet's NEO・SharePoint Online の資料・問い合わせの記録に書かない。渡すときは、DX推進部が決めた安全な方法（期限つきの共有など）を使う
  • キーをGitのリポジトリや生成ツールのフォルダ（tools/）に入れない。kinds.js・specs.json にも書かない
  • 試験用のキーや localhost の許可は、試験が終わったら消す
  • キーの一覧（名前・使い道・作った日・入れかえ予定日）を管理表（付録C）に残す。キーの値は書かない
  • 利用者のブラウザには mirai-kensetsu-site-portal-google3d-key という名前で保存される（キーの画面で「このブラウザに保存する」にチェックしたとき。初期はチェックあり）。共用のPCでは保存しないよう案内する。原本のポータルで保存したキーは当社版には引き継がれない

8.2定期的な入れかえ（3か月ごとをすすめる）

  1. 3.4 の手順で、同じ制限の新しいキーを作ります。
  2. キーを書きこんでいる場合は、5.3 の手順で新しいキーの版を作って切りかえます。書きこんでいない場合は、利用者に新しいキーを配り、🔑 APIキー から入れ直してもらいます。
  3. 1〜2日、新しいキーで使えていることを確かめます（6.3 の指標）。
  4. 古いキーを 認証情報 の画面で削除します。
  5. 管理表を更新します。

8.3キーが漏れたかもしれないとき

キーがメールに書かれた、画面の写しに写った、社外に配られた、Google の数が急に増えた、などに気づいた人は、すぐ DX推進部へ知らせます。DX推進部は次を行います。

すぐにやること（順番どおり）
  1. Google Cloud の 認証情報 で、そのキーを削除します。削除したキーは、すぐに使えなくなります。
  2. 新しいキーを作り（3.4）、ポータルを切りかえます（5.3）。キーを書きこんでいない場合は、必要な利用者に新しいキーを配ります。
  3. お支払い → レポート と Map Tiles API の指標で、いつから・どれだけ使われたかを確かめます。
  4. 「情報セキュリティ事故対応マニュアル」に従って報告し、事故として記録します。報告の宛先・期限・様式は、マニュアルの本文で確かめてください。思わぬ料金が出ていれば、Google Cloud のサポートに相談します。
  5. 漏れた原因（ファイルの配布、画面の写真、Git など）を調べ、同じことが起きないようにします。

10障害への対応

利用者からの連絡先は DX推進部です。利用手順書でも、DX推進部を連絡先として案内します。

サーバ版では、まず 19章

ログインできない・データが出ない・ページが開かないときは、まず 19章（サービスの状態・journalctl・/healthz）を確かめます。下の表の nginx・証明書の行は、nginx を使う場合のものです。

10.1切り分けの順番

  1. どこまで開けるかを利用者に聞きます：ページ自体が開かない／開くが3Dが出ない／簡易地形は出るが Google 3D が出ない。
  2. 右上の札と、赤い枠の原因を教えてもらいます（キーは聞かない）。
  3. どこから開いているかを聞きます：本社・支店・作業所の社内網／FortiClient の SSL-VPN／それ以外。
  4. 1人だけか、全員か、ある拠点だけかを確かめます。全員ならサーバか FortiGate、ある拠点だけならその拠点の経路、1人ならそのPCかブラウザが原因のことが多いです。
  5. FortiGate の許可漏れかを確かめます。社内網からだと Google 3D や3D表示が出ないのに、社内網の外（DX推進部の試験用の回線など）では出るときは、FortiGate の許可漏れ・Webフィルタ・SSL検査を疑います。FortiGate の記録で、tile.googleapis.com・cdn.jsdelivr.net への通信が拒否されていないかを見ます。ブラウザの開発者ツール（F12 → ネットワーク）で、失敗している宛先を確かめることもできます。
  6. 下の表で原因を絞り、直したら利用者に Ctrl＋F5 で開き直してもらいます。

19障害時の確認

19.1切り分けの順番

  1. サービスは動いているか：systemctl --user status mirai-3d-portal。「condition failed」ならルートのフォルダか server/.env が見えていません（USB HDD の接続を確かめる）。再起動をくり返して止まった（start-limit）ときは、原因を直してから systemctl --user reset-failed mirai-3d-portal → start。
